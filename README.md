# how-sgd-works

확률적 경사 하강법(SGD)은 어떻게 동작하는가 — **전부 보지 않고 내려가는 법**. 미니배치 기울기가 왜 진짜 기울기의 불편 추정량인지, 그 오차가 왜 하필 1/√B로 줄어드는지, 같은 계산 예산에서 GD와 붙으면 누가 이기는지, 그리고 그 노이즈가 왜 버그가 아닌지를 브라우저에서 직접 계산해 보는 인터랙티브 교육 자료입니다.

## 한 문단 요약

거의 모든 지도학습의 손실은 **샘플별 손실의 평균**이고, 따라서 기울기도 평균입니다. 경사 하강법(GD)은 그 평균을 구하려고 **한 발짝마다 데이터 전부**를 통과시킵니다 — ImageNet이면 가중치를 한 번 고치는 데 128만 장. SGD는 무작위로 뽑은 B개의 평균으로 대신합니다. 균등하게 뽑는 한 **미니배치 기울기의 기댓값은 진짜 기울기와 정확히 같고**(불편 추정량), 틀리는 정도(RMS)는 `√(S²/B · (N−B)/(N−1))` — 즉 **1/√B**로만 줄어듭니다. 배치를 4배 키워야 노이즈가 절반이라는 뜻이라, 계산량당으로 보면 큰 배치는 손해입니다. 대신 같은 예산에서 SGD는 **N/B배 더 많이 움직이고**, 이 자료의 경주 데모에서는 1에폭 시점에 최솟값까지 남은 거리가 **B=1은 0.023, GD는 6.44**로 벌어집니다. 노이즈에는 부수 효과도 있습니다 — ∇L = 0인 지점에서 GD는 영원히 멈추지만 SGD는 계속 흔들려 얕은 웅덩이를 빠져나옵니다(데모에서 σ=0이면 탈출률 0%, σ=3이면 40% 안팎). 그 대가로 SGD는 최솟값에 **정착하지 못하고** 반경 ∝ √η의 노이즈 볼 안을 맴돌기 때문에 학습률을 줄여야 하고, 얼마나 줄여야 하는지가 `Ση_t = ∞, Ση_t² < ∞`라는 **1951년 Robbins–Monro 조건**입니다. 여러 대로 나눠 돌릴 때도 같은 이야기가 이어집니다 — **동기 SGD는 배치를 키우는 것과 수학적으로 완전히 같은 일**이라 새로울 게 없지만(데모에서 두 궤적의 차이 10⁻¹⁶), 기다리지 않는 **비동기 SGD는 지연된 기울기가 *편향*이라 §2의 불편성이 깨집니다.**

## 이 페이지가 답하는 질문

- 방향이 틀린 기울기로 내려가도 왜 괜찮은가? (기댓값이 맞으면 된다 — 대신 분산이 붙는다)
- 배치 크기를 2배 키우면 학습이 2배 좋아지나? (노이즈는 √2배만 줄어든다)
- "1 에폭"은 왜 진척도의 단위가 아닌가? (GD에겐 1스텝, B=256·N=128만이면 5,005스텝)
- 손실 곡선이 평평해졌다 = 다 배웠다? (노이즈 볼에 닿은 것일 수 있다 — 학습률을 낮춰 보면 구분된다)
- 학습률은 왜 줄여야 하고, 얼마나 줄여야 하는가? (`Ση = ∞, Ση² < ∞`)
- `shuffle=True`는 그냥 관례인가? (아니다 — 에폭 안에서 오차가 상쇄돼 i.i.d. 추출보다 바닥이 더 낮다)
- `torch.optim.SGD`를 쓰면 배치 크기가 1인가? (아니다 — 배치는 DataLoader가 정한다)
- GPU를 8장으로 늘리면 새로운 알고리즘이 되는가? (아니다 — 동기 SGD는 배치를 8배 키우는 것과 완전히 같은 식이다)
- 비동기 SGD의 지연된 기울기는 그냥 노이즈가 좀 더 낀 것인가? (아니다 — 평균이 0이 아닌 **편향**이라 상쇄되지 않는다)
- 비동기가 빠른데 왜 요즘은 동기를 쓰는가? (통신이 싸졌고, 비동기는 워커를 늘릴수록 쓸 수 있는 학습률이 작아진다 · 재현되지 않아 디버깅이 안 된다)

## GD와 SGD의 차이 — 한 장 요약

| | 배치 GD | 미니배치 SGD | SGD (B=1) |
|---|---|---|---|
| 한 스텝에 쓰는 샘플 | N (전부) | B | 1 |
| 1 에폭당 갱신 | 1회 | N/B회 | N회 |
| 기울기 | 정확 | 기댓값만 정확 (오차 ∝ 1/√B) | 기댓값만 정확 |
| 수렴 지점 | 최솟값에 정착 | 최솟값 주변 노이즈 볼 (반경 ∝ √η) | 더 넓은 노이즈 볼 |
| ∇L = 0인 지점 | 영원히 못 나옴 | 흔들려서 빠져나올 수 있음 | 〃 |
| 온라인 학습 | 불가 | 가능 | 가능 |
| GPU | 메모리 초과 | 최적 | 병렬성 없음 |

## 숫자에 대하여

장난감 문제는 **N = 40개 점에 직선을 맞추는 선형 회귀**(`y = 2x + 1 + 잡음`)입니다. 파라미터가 `(w, b)` 둘뿐이라 손실 지형을 평면에 그릴 수 있고, 진짜 기울기와 최적해(`θ* = (2.1624, 1.1526)`, `L* = 0.38589`)를 닫힌 형태로 계산할 수 있어 "추정이 얼마나 틀렸는가"를 정확히 잴 수 있습니다. 데이터는 고정 시드로 생성되므로 새로고침해도 같은 지형이 나옵니다. 페이지의 모든 수치 — 등고선, 화살표, 궤적, RMS 측정, 경주 곡선, 탈출률, 노이즈 볼의 바닥 — 는 브라우저 안에서 실제로 돌린 결과이며, 하드코딩된 값이 아닙니다.

§9의 벽시계 경주는 워커별 처리 시간을 난수로 뽑는 **이산 사건 시뮬레이션**입니다 — 통신 비용과 대역폭 경합은 모형에 넣지 않았고, 시간 단위도 "보통 워커가 미니배치 하나를 처리하는 시간"이라는 상대 단위입니다. 그 위에서 도는 SGD 갱신과 지연 계산은 전부 실제입니다. §6의 탈출 데모는 예외적으로 **1차원 이중 우물 + 평균 0의 가우시안 노이즈**라는 단순화된 모형입니다. 실제 SGD의 노이즈는 위치에 따라 크기와 방향이 달라지고 가우시안도 아니며, 깊은 신경망에서 문제가 되는 것은 지역 최솟값보다 안장점([Dauphin et al., 2014](https://arxiv.org/abs/1406.2572))이라는 관점이 우세합니다. 페이지 안에도 같은 주의를 적어 두었습니다.
